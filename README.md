# Framefit

CLI, по которому агент верстает экран или компонент по фрейму Figma и сам проверяет результат. Рассчитан и на неаккуратные макеты: без auto layout, с кучей слоёв на одном уровне.

Экран принят, когда сошлись три проверки:

- **Картинка.** Скриншот сравнивается с PNG фрейма через [pixelmatch](https://github.com/mapbox/pixelmatch). Сглаживание и сдвиги до 1 px не считаются ошибкой.
- **Геометрия текста.** Каждая строка макета ищется на странице по содержимому, а не по слоям Figma. Сверяются положение, размер, шрифт, вес, кегль, line-height и цвет.
- **Вёрстка.** Нельзя ставить текст через `absolute`/`fixed`, двигать его `top/left`, `transform` или отрицательным margin. Текст не должен вылезать или обрезаться, в том числе когда строки длиннее, а окно шире или уже.

Playwright и подмена запросов живут внутри CLI, в проект экрана ничего ставить не нужно.

## Установка

Нужны Node 20+ и Google Chrome (или `npx playwright install chromium`).

```bash
git clone <адрес-репозитория> framefit
cd framefit
npm install && npm run build && npm link
```

После `npm link` команда `framefit` доступна в любом терминале. Обновление: `git pull && npm run build`.

## Подключение агента

1. Скопируйте `skill/SKILL.md` в папку навыков: `~/.cursor/skills/framefit/SKILL.md` для Cursor или `~/.claude/skills/framefit/SKILL.md` для Claude Code. Можно положить и в репозиторий проекта (`.cursor/skills/…`, `.claude/skills/…`), тогда skill будет у всей команды.
2. Дайте доступ к Figma одним из способов:
   - **Токен (лучше).** В Figma: Settings → Security → Personal access tokens, scope на чтение файлов. Положите его в переменную окружения `FIGMA_TOKEN`. Хватает права на просмотр макета.
   - **Figma MCP.** Нужен аккаунт с правом на редактирование файла, просмотра мало.

## Как пользоваться

Один раз на машине:

1. Установите framefit (раздел «Установка») и проверьте, что `framefit --help` работает.
2. Скопируйте skill и дайте доступ к Figma (раздел «Подключение агента»).

На каждую задачу:

1. Скопируйте ссылку на фрейм: правый клик по фрейму → Copy link to selection. В ссылке должен быть `node-id`.
2. Проверьте доступ к макету: с токеном хватает просмотра, через MCP нужно право на редактирование. Если его нет, сделайте копию файла в своём аккаунте и дайте ссылку на фрейм в копии.
3. Поднимите проект локально и откройте страницу, где будет жить компонент.
4. Откройте в Cursor новый чат в этом проекте и отправьте промпт по шаблону ниже.
5. Дождитесь итога. Агент сам скачивает эталон, пишет фикстуру, верстает и гоняет `check` и `stress`, пока оба не вернут 0, но не больше 8 кругов. Если PNG фрейма получить не удалось, он останавливается и просит доступ.
6. Посмотрите `.framefit/diff.png`, `stress-*.png` и сам код. Закоммитьте только код компонента, `.framefit` должен быть в `.gitignore` проекта.

## Промпты

### Рабочий проект

```text
Сверстай <что, например «карточку новой акции»> по фрейму <ссылка с node-id>.
Образец: src/widgets/promo/PromoCard.tsx — повтори его структуру и используй те же компоненты дизайн-системы. Новый компонент положи в src/widgets/promo/.
Страница: http://localhost:3000/promo, корень компонента: [data-testid=promo-card] (передавай его в --selector, вьюпорт 1280x900).
Данные приходят из GET /api/promo/:id — замокай их фикстурой framefit, бэкенд не трогай.
Шрифт <название> уже подключён в проекте.
Работай по skill framefit: check и stress до кода 0, не больше 8 кругов. Не меняй файлы вне src/widgets/promo.
```

Что должно быть в промпте и зачем:

| Что | Зачем |
| --- | --- |
| ссылка на фрейм с `node-id` | без неё агент не знает, что сверять |
| компонент-образец и папка для нового | иначе агент придумает свою архитектуру вместо вашей |
| адрес страницы и селектор компонента | без `--selector` в кадр попадёт вся страница с шапкой и сайдбаром |
| откуда приходят данные | иначе тексты окажутся захардкожены в компоненте, а не в фикстуре |
| границы правок | иначе агент может «улучшить» общие стили или дизайн-систему |

### demo в этом репозитории

`demo` — пустой React + Vite проект для пробы. Запустите `cd demo && npm run dev` и отправьте:

```text
Сверстай экран по фрейму <ссылка с node-id> в demo (React + Vite, обычный CSS).
Начни с пустого demo/src/main.tsx, компоненты положи в demo/src.
Данные, которые на реальном экране пришли бы с бэкенда, отдавай через fetch('/api/<имя>') и клади в demo/mock/<имя>.json.
Сервер уже запущен: http://127.0.0.1:4174/.
Работай по skill framefit: check и stress до кода 0, не больше 8 кругов.
В конце покажи diff.png, итог отчёта и напиши, сколько кругов понадобилось и на чём буксовал.
```

Последняя строка нужна для оценки самого инструмента: она показывает, где skill или проверки мешают агенту.

## Команды

```bash
framefit pull --figma "https://www.figma.com/design/KEY/Name?node-id=1-3"
framefit check  --url http://localhost:3000/screen --reference .framefit/reference.png --fixture .framefit/fixture.json
framefit stress --url http://localhost:3000/screen --reference .framefit/reference.png --fixture .framefit/fixture.json
```

`pull` берёт `FIGMA_TOKEN` из окружения и пишет в `.framefit` четыре файла:

- `reference.png` и `reference@2x.png` — PNG фрейма;
- `design.json` — строки макета с боксами, шрифтами и цветами;
- `fixture.draft.json` — черновик фикстуры со всеми строками.

`check` сравнивает страницу с эталоном. `design.json` рядом с эталоном подхватывается сам.

`stress` с макетом не сравнивает. Он удлиняет каждую строку вдвое и проверяет страницу в окне шире и уже на 15%. Затем укорачивает строки до одной буквы и проверяет, что ничего не схлопнулось.

Компонент внутри страницы или Storybook: снимается и проверяется только элемент по селектору. URL берите в кавычки, иначе zsh споткнётся о `?`.

```bash
framefit check --url "http://localhost:6006/iframe.html?id=promo-card" \
  --selector "[data-testid=promo-card]" --viewport 1280x900 \
  --reference .framefit/reference.png --fixture .framefit/fixture.json
```

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `--out` | `.framefit` | куда писать результат |
| `--selector` | — | снимать и проверять только этот элемент |
| `--viewport` | размер эталона | размер окна, `1280x900` |
| `--scale` | `1` | масштаб эталона: `2` для `reference@2x.png` |
| `--design` | `design.json` рядом с эталоном | файл с текстами макета |
| `--threshold` | `0.02` | допустимая доля отличающихся пикселей во всём кадре |
| `--ink-threshold` | `0.1` | то же, но только среди пикселей текста и иконок |
| `--tolerance` | `1` | допустимый сдвиг строки в px |
| `--wide`, `--narrow` | `1.15`, `0.85` | во сколько раз stress расширяет и сужает окно, `--narrow 1` выключает сужение |

## Результат

В каталоге `--out`:

- `actual.png` — скриншот;
- `diff.png` — эталон в сером, расхождения красным;
- `check.json`, `stress.json` — отчёты, `report.json` — копия последнего;
- `stress-wide.png`, `stress-narrow.png`, `stress-short.png` — страница в фазах stress.

Коды выхода:

| Код | `check` | `stress` |
| --- | --- | --- |
| 0 | всё сошлось | вёрстка выдержала |
| 2 | не сошлись картинка или геометрия | — |
| 3 | не сошлась только вёрстка | вёрстка не выдержала |
| 4 | не сошлось и то, и другое | — |
| 1 | ошибка запуска | ошибка запуска |

Код 1 значит, что страница или элемент недоступны или размер скриншота не совпал с эталоном. Вёрстку из-за него не трогают: нужно поднять сервер или заново снять эталон. С `--selector` разный размер компонента и эталона — уже ошибка вёрстки, код 2.

Что значат строки отчёта:

| Строка | Смысл |
| --- | --- |
| `!область x,y WxH — селектор «текст»` | плотное расхождение и элементы под ним; `!` значит, что из-за него check не прошёл |
| `~область …` | расхождение лежит на строке, геометрия которой в норме: Figma и Chrome по-разному рисуют глифы. На результат не влияет |
| `геометрия: «текст» …: сдвиг по y +2px` | строка не на месте, или не совпали шрифт, вес, кегль, line-height, цвет |
| `нет на странице` / `нет в макете` | строка макета не найдена / лишний текст на странице |
| `текст в absolute/fixed`, `подгонка …` | текст поставлен координатами или подвинут сдвигом |
| `overflow`, `обрезан текст` | текст не влезает в коробку; в скобках фаза stress |
| `схлопнулся при коротком тексте` | размер коробки держался только на длине строки |
| `шрифты: … (missing)` | шрифт не загрузился, сравнение пикселей недостоверно |
| `без мока`, `маршрут не вызван` | страница ходит не туда, куда смотрит фикстура |

Два атрибута снимают проверки точечно:

- `data-framefit-overlay` — на настоящий оверлей вроде бейджа поверх фото. Внутри него можно `absolute`.
- `data-framefit-truncate` — на текст, который обрезан по макету (ellipsis, line-clamp).

## Фикстура и design.json

Фикстура подменяет запросы страницы на время прогона:

- `routes` — ответы на `fetch` и XHR;
- `assets` — картинки и шрифты, пути считаются от файла фикстуры;
- `ignore` — зоны, которые не сравниваются: часы, статус-бар, живой баннер.

URL задаётся glob-паттерном, `**` захватывает несколько сегментов пути.

```json
{
  "ignore": [{ "x": 0, "y": 0, "width": 390, "height": 44 }],
  "routes": [{ "method": "GET", "url": "**/api/promo", "json": { "title": "Акция" } }],
  "assets": [{ "url": "**/media/cover.png", "file": "./cover.png" }]
}
```

`design.json` пишет `pull`. Без токена его собирает агент через MCP. Координаты в CSS-пикселях от левого верхнего угла фрейма. Бокс должен просто накрывать текст: положение меряется по самим буквам на эталоне.

```json
{
  "frame": { "width": 350, "height": 506 },
  "fonts": ["Golos Text"],
  "texts": [
    { "text": "Льняной пиджак", "x": 20, "y": 250, "width": 214, "height": 32,
      "fontFamily": "Golos Text", "fontWeight": 700, "fontSize": 28, "lineHeight": 32, "color": "#29211d" }
  ]
}
```

## Ограничения

- Сдвиги строки на 1–2 px пиксели не ловят, их ловит только геометрия. Без `design.json` такие ошибки проходят.
- Пороги проверены на одном настоящем макете и синтетических тестах. На первых рабочих макетах проверьте, что правильно сверстанный экран проходит.
- Только Chromium и только веб.

## В рабочем проекте

Добавьте `.framefit` в `.gitignore` проекта: эталоны, скриншоты и отчёты локальные. В репозиторий идёт только код компонента.
